# 김성현 데이터·머신러닝 담당 설명서

## 이 문서의 목적

이 문서는 실제 구현 순서를 이해하고 발표와 질의응답을 준비하기 위한 개인 학습 노트이다. 현재 구현된 기능과 앞으로 구현할 계획을 구분하며, 수행하지 않은 작업이나 확인하지 않은 성능을 완료했다고 표현하지 않는다.

## 현재 완료된 범위

- 2024년 1월~2026년 8월 실제 교통량 수집과 검증
- 와이드 데이터를 시간당 한 행의 롱 형식으로 변환
- 4개 생활권의 교차로 12개와 접근로 44개 선정
- 선정 데이터 1,028,544행의 EDA와 센서 이상 의심 구간 표시
- 과거 1·2·3·24·168시간 교통량과 3·6시간 이동 통계 생성
- 학습·검증·시험 시간순 분할
- 학습 구간만 사용한 접근로별 90백분위수 계산
- 데이터·입력 변수 불변 조건을 확인하는 자동 테스트

## 아직 하지 않은 범위

- 기상·공휴일 자료 결합
- 단순 기준, Ridge와 트리 모델 학습
- 실제 검증 성능 비교와 최종 모델 선정
- FastAPI와 Streamlit 연결

## 내가 담당하는 범위

김성현의 주 담당은 데이터와 머신러닝이다.

```text
원본 확인
→ 전처리
→ EDA
→ 입력 변수 생성
→ 시간순 데이터 분할
→ 단순 기준과 Ridge 구현
→ 팀원의 후보 모델 결과 취합
→ 최종 모델 비교·선정
```

백엔드와 프론트엔드를 대신 구현하는 것이 아니라 두 담당자가 사용할 데이터 구조, 모델 입력과 출력 규칙을 제공한다.

## 전체 프로젝트에서 데이터와 ML의 위치

```text
천안시 원본 데이터
→ 데이터·ML 담당: 정제와 학습
→ final_model 파일과 입력 규칙
→ 백엔드 담당: FastAPI로 모델 호출
→ 프론트엔드 담당: Streamlit에서 사용자에게 결과 표시
```

모델 학습은 FastAPI나 Streamlit에서 수행하지 않는다. 학습 코드를 개발 환경에서 실행해 최종 모델 파일을 만든다. 서비스는 저장된 모델을 불러와 예측만 수행한다.

## 가공 전 원본 데이터

가공 전 원본 한 행은 한 날짜·교차로·접근로의 하루 교통량을 나타낼 것으로 예상한다.

```text
일자 | 교차로명 | 접근로명 | 합계 | 00시 | 01시 | ... | 23시
```

시간대별 차량 대수 24개가 옆으로 펼쳐져 있으므로 와이드 형식이라고 한다.

현재 저장소의 `data/sample/cheonan_traffic_wide_sample.csv`는 코드 검증을 위해 직접 만든 합성 예제이다. 실제 천안시 교통량으로 해석하면 안 된다.

## 와이드 형식과 롱 형식

와이드 형식은 한 날짜의 24시간 값이 여러 열에 놓인 형태이다.

```text
2024-01-01 | 합성A교차로 | 동쪽접근로 | 20 | 21 | ... | 43
```

롱 형식은 한 시간의 관측값이 한 행을 이루는 형태이다.

```text
2024-01-01 00:00 | 합성A교차로 | 동쪽접근로 | 20
2024-01-01 01:00 | 합성A교차로 | 동쪽접근로 | 21
```

모델은 각 시점의 입력과 정답을 행 단위로 받는 것이 편리하다. 롱 형식으로 바꾸면 시간순 정렬, 최근 교통량 조회, 지연 변수 생성과 학습·검증 기간 분리가 쉬워진다.

발표 답변:

> 원본은 하루 24시간의 교통량이 열로 저장된 와이드 형식입니다. 이를 교차로·접근로·시각마다 한 행이 되도록 롱 형식으로 바꾸어 시간의 흐름을 학습할 수 있게 합니다.

## EDA란 무엇인가

EDA는 탐색적 데이터 분석이다. 모델을 학습하기 전에 데이터가 실제로 어떤 상태인지 확인하는 과정이다.

이 프로젝트에서는 다음을 확인한다.

- 날짜별·시간대별 행 수
- 교차로와 접근로 개수
- 결측과 중복
- 음수와 장기 0값
- 관측 시작일과 종료일
- 교차로·접근로 명칭 변경
- 평일·주말·출퇴근 시간대 패턴
- 접근로별 교통량 규모 차이

EDA의 목적은 예쁜 그래프를 만드는 것이 아니라 어떤 데이터를 학습에 포함할지 근거를 만드는 것이다.

## 입력 변수와 정답

입력 변수는 모델에게 제공하는 힌트이고 정답은 모델이 맞혀야 하는 값이다.

오전 9시 교통량을 예측하는 예시는 다음과 같다.

```text
입력 변수
예측 시각: 오전 9시
요일: 월요일
교차로와 접근로
오전 8시 교통량
오전 7시 교통량
전날 오전 9시 교통량
전주 같은 요일 오전 9시 교통량
최근 3시간·6시간 평균
예측 시점에 알 수 있는 날씨

정답
오전 9시 실제 교통량
```

사용자는 이 숫자를 전부 직접 입력하지 않는다. 사용자는 교차로·접근로·기준 시각만 선택하고, 시스템이 저장된 데이터에서 나머지 입력을 조회하거나 계산한다.

## 시간 특성

시간 특성은 예측하려는 시점이 언제인지를 나타낸다.

- 시각
- 요일
- 월
- 주말 여부
- 공휴일 여부

교통량은 오전 3시와 오전 8시가 다르고 평일과 주말도 다르므로 반복 패턴을 알려주기 위해 사용한다.

## 과거 교통량과 지연 변수

지연 변수는 예측 시점보다 과거의 교통량을 입력으로 사용하는 값이다.

오전 9시를 예측할 때의 예시는 다음과 같다.

| 변수 | 의미 |
|---|---|
| `lag_1` | 오전 8시 교통량 |
| `lag_2` | 오전 7시 교통량 |
| `lag_24` | 전날 오전 9시 교통량 |
| `lag_168` | 전주 같은 요일 오전 9시 교통량 |

최근 값은 현재 흐름을 나타내고 24시간과 168시간 전 값은 하루·일주일 반복 패턴을 나타낸다.

## 최근 3시간·6시간 평균

이동 평균은 최근 여러 시간의 교통량을 평균낸 값이다. 한 시간의 순간적인 흔들림을 완화하고 최근 전체 흐름을 전달한다.

3시간은 빠른 변화, 6시간은 조금 더 완만한 최근 흐름을 보기 위한 초기 후보이다. 3시간과 6시간이 이론적으로 유일한 정답은 아니다. 4시간과 7시간도 사용할 수 있으며 실제 시간순 검증에서 후보를 비교할 수 있다. 비슷한 변수를 무제한 추가하면 과적합과 중복 가능성이 커지므로 선택 근거가 있는 후보만 사용한다.

## 데이터 누출

데이터 누출은 실제 예측 시점에는 알 수 없는 미래 정보가 학습 과정에 들어가 성능이 실제보다 좋아 보이는 문제이다.

누출 예시는 다음과 같다.

- 오전 9시를 예측하면서 오전 9시 이후의 교통량을 이동 평균에 포함
- 전체 기간으로 평균과 스케일러를 계산한 뒤 과거 학습 자료에 적용
- 시험 기간을 반복해서 확인하며 모델을 선택
- 미래의 실제 관측 날씨를 알고 있었던 것처럼 사용

모든 지연 변수와 이동 평균은 해당 시점보다 과거 값만으로 계산한다. 결측 대체값, 스케일러와 90백분위수도 학습 기간에서만 계산한다.

## 무작위 분할을 사용하지 않는 이유

교통량은 시간 순서가 있는 데이터이다. 무작위로 섞으면 2026년 자료로 학습하고 2024년을 시험하는 상황이 생길 수 있다. 실제 서비스에서는 미래를 미리 볼 수 없으므로 과거로 학습하고 이후 기간으로 평가한다.

Randomized Search는 데이터 무작위 분할과 다르다. 데이터 순서는 유지하고 트리 깊이, 트리 수와 학습률 같은 모델 설정 후보만 무작위로 골라 비교한다.

## 학습·검증·시험 데이터

| 구간 | 역할 |
|---|---|
| 학습 | 모델이 패턴을 배우는 자료 |
| 검증 | 모델 종류와 설정값을 선택하는 자료 |
| 시험 | 모든 선택이 끝난 뒤 최종 성능을 한 번 확인하는 자료 |

현재 계획은 2024~2025년 학습, 2026년 1~5월 검증, 2026년 6~8월 시험이다. 실제 확보 자료와 품질에 따라 경계일은 조정할 수 있지만 시간 순서는 유지한다.

## 단순 기준 모델

단순 기준은 복잡한 모델의 가치가 있는지 판단하는 비교 대상이다.

- 다음 시간도 현재 시간과 같다고 예측
- 전날 같은 시간 값을 사용
- 전주 같은 요일·시간 값을 사용
- 학습 기간의 접근로·요일·시간 평균 사용

교통량은 반복성이 강하므로 복잡한 모델이 이 기준보다 좋아지지 않는다면 서비스에 복잡한 모델을 사용할 이유가 부족하다.

## 여러 모델을 학습하는 이유

Ridge, Random Forest, HistGradientBoosting, XGBoost와 CatBoost는 모두 한 시간 후 교통량을 예측하는 후보이다. 동일한 데이터와 시간순 검증 구간으로 각각 학습한 뒤 MAE, WAPE, RMSE와 기간별 안정성을 비교한다.

모든 모델을 서비스에 동시에 넣는 것이 아니다. 가장 정확하고 안정적인 모델 하나를 최종 선택한다. 부스팅 모델이 유력 후보이지만 Random Forest나 Ridge가 실제 검증에서 더 안정적이면 해당 모델을 선택할 수 있다.

## 회귀 평가 지표

### MAE

실제값과 예측값 차이의 절댓값을 평균낸다. MAE가 30이면 평균적으로 약 30대를 틀렸다는 뜻이다. 단위가 차량 대수라 가장 직관적이다.

### WAPE

전체 절대오차를 전체 실제 교통량으로 나눈 비율이다. 교차로나 기간의 교통량 규모가 달라도 상대적인 오차를 비교할 수 있다.

### RMSE

오차를 제곱해서 평균낸 뒤 제곱근을 구한다. 큰 오차에 더 큰 벌점을 주므로 특정 출퇴근 시간에 심각하게 빗나가는 모델을 찾는 데 유용하다.

세 지표는 모두 낮을수록 좋다. MAE는 평균 오차, WAPE는 상대 오차, RMSE는 큰 실패를 확인한다.

## 고교통량 평가 지표

### Recall

실제 고교통량 시간 중 모델이 찾아낸 비율이다. 높을수록 실제 고교통량을 적게 놓친다.

### Precision

모델이 발생시킨 경보 중 실제 고교통량이었던 비율이다. 높을수록 거짓 경보가 적다.

### F1

Recall과 Precision의 균형이다. 하나만 높고 다른 하나가 낮으면 F1도 낮아진다.

### PR-AUC

경보 기준을 바꾸었을 때 Precision과 Recall의 관계를 전체적으로 평가한다. 고교통량처럼 전체 중 적게 발생하는 사건에 적합하다.

단순 정확도를 주 지표로 사용하지 않는다. 상위 10%만 고교통량이라면 모든 시간을 일반으로 예측해도 정확도가 약 90%로 보일 수 있지만 실제 고교통량은 하나도 찾지 못한다.

## 현재 코드 실행 순서

저장소 루트에서 실행한다.

환경을 설치한다.

```bash
python -m pip install -r requirements.txt
```

합성 원본을 검사한다.

```bash
python src/data/inspect_raw.py --input data/sample/cheonan_traffic_wide_sample.csv
```

입력 파일:

```text
data/sample/cheonan_traffic_wide_sample.csv
```

출력:

```text
행·열 수
열 이름
교차로·접근로 수
중복·결측·음수·0값 통계
```

롱 형식으로 변환한다.

```bash
python src/data/wide_to_long.py --input data/sample/cheonan_traffic_wide_sample.csv --output data/interim/cheonan_traffic_long_sample.csv
```

출력 파일:

```text
data/interim/cheonan_traffic_long_sample.csv
```

합성 원본은 8행이므로 변환 결과는 `8 × 24 = 192행`이어야 한다.

자동 테스트를 실행한다.

```bash
python -m pytest
```

## 문제 발생 시 확인 항목

### 필수 시간 열이 없다는 오류

실제 원본에 00시~23시가 모두 있는지 확인한다. `0시`처럼 형식이 달라도 코드는 인식하지만 누락된 시간은 자동 생성하지 않는다.

### 일자·교차로·접근로 중복 오류

같은 키가 정말 중복인지, 서로 다른 차로나 방향을 구분하는 추가 열이 있는지 원본에서 확인한다. 임의로 첫 행만 남기지 않는다.

### 숫자로 변환할 수 없는 교통량

`-`, 쉼표, 문자열이나 주석이 들어 있는지 확인한다. 원본 의미를 확인하기 전 0으로 바꾸지 않는다.

### 인코딩 오류

코드는 UTF-8과 CP949 CSV를 시도한다. 다른 인코딩이면 원본 다운로드 방식과 확장자를 확인한다.

### Parquet 저장 오류

`pyarrow`가 설치되어 있는지 확인한다.

```bash
python -m pip install -r requirements.txt
```

## 예상 질문과 짧은 답변

### 왜 모델링을 합니까?

과거와 현재 조회만으로는 한 시간 후 교통량을 알 수 없으므로 시간·과거 교통량·날씨의 관계를 학습하여 미래 값을 예측하기 위해서이다.

### 입력 변수는 사용자가 직접 입력합니까?

사용자는 교차로·접근로·기준 시각만 선택한다. 과거 교통량, 시간 특성과 날씨는 시스템이 자동으로 조회하거나 계산한다.

### 왜 모든 교차로를 사용하지 않습니까?

교차로 개수보다 관측 연속성과 데이터 품질을 우선하고, 품질이 좋은 범위에서 완성한 뒤 확장하기 위해서이다.

### 왜 3시간·6시간 평균입니까?

짧은 변화와 조금 더 완만한 최근 흐름을 비교하기 위한 초기 후보이다. 고정된 정답은 아니며 다른 시간 창도 시간순 검증으로 비교할 수 있다.

### 왜 여러 모델을 학습합니까?

특정 모델이 항상 최고라는 보장이 없으므로 동일한 조건에서 비교하고 검증 오차와 안정성이 가장 좋은 모델을 선택하기 위해서이다.

### 왜 무작위 분할을 사용하지 않습니까?

미래 정보가 학습에 섞여 성능이 실제보다 좋아 보이는 시간 누출을 막기 위해서이다.

### 왜 MAE, WAPE, RMSE를 함께 사용합니까?

평균적인 차량 대수 오차, 전체 교통량 대비 상대 오차와 큰 예측 실패를 각각 확인하기 위해서이다.

### SHAP은 원인을 설명합니까?

SHAP은 모델이 이번 예측에서 중요하게 사용한 입력을 설명하지만 실제 인과관계를 증명하지는 않는다.
