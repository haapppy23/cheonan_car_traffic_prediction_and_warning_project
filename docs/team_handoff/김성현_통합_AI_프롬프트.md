# 김성현 통합 작업용 AI 프롬프트

팀원이 브랜치 주소와 커밋 해시를 보낸 뒤 아래 내용을 AI에게 전달한다. 괄호 부분은 실제 값으로 바꾼다.

```text
천안시 스마트교차로 교통량 예측 프로젝트의 팀원 브랜치를 검토하고 통합한다.

저장소:
https://github.com/haapppy23/cheonan_car_traffic_prediction_and_warning_project

검토 대상:
- 이나율 백엔드 브랜치: (브랜치명 또는 커밋 해시)
- 김문일 프론트엔드 브랜치: (브랜치명 또는 커밋 해시)

이 요청은 검토 방법 설명이 아니라 실제 브랜치 검증과 통합 작업 요청이다. 계획만 제시하고 멈추지 말고 fetch, diff 검토, 테스트, 안전한 반영, 전체 연동 검증과 push까지 직접 진행하라. 범위 안의 안전한 결정은 저장소 근거로 판단하고 불필요한 확인 질문을 하지 마라. 충돌이나 테스트 실패가 있으면 원인을 좁혀 수정 가능한 통합 문제는 해결하고, 팀원 코드 자체의 명백한 결함이면 근거가 있는 수정 요청을 작성하라.

GitHub 로그인·권한 승인이나 팀원 브랜치 식별값 누락처럼 사용자가 직접 해결해야 하는 사항만 질문할 수 있다. 원격 main의 최종 커밋이 로컬 HEAD와 같은지 확인하기 전에는 완료했다고 보고하지 마라.

먼저 AGENTS.md와 docs/team_handoff/README.md를 읽어라. 현재 작업을 보존한 상태에서 origin을 fetch하고 각 브랜치의 diff, 커밋과 테스트를 확인하라. 팀원이 실제로 작성한 변경을 대신 다시 구현하지 마라.

통합 순서:
- 이나율 브랜치부터 검토한다.
- /locations 계약, 기존 /health와 /predict 보존, 테스트 통과를 확인한다.
- 문제가 있으면 파일과 줄을 근거로 수정 요청안을 작성하고 병합하지 않는다.
- 문제가 없으면 백엔드 변경을 main에 반영한다.
- 최신 main을 기준으로 김문일 브랜치를 검토한다.
- 프론트엔드가 모델을 직접 읽지 않고 API만 호출하는지 확인한다.
- 정상·오류 응답 처리와 테스트 통과를 확인한 뒤 반영한다.

최종 검증:
- python -m pytest -q
- python -m compileall -q backend frontend src tests
- git diff --check
- FastAPI와 Streamlit을 함께 실행한다.
- 교차로와 접근로를 선택해 실제 예측 한 건을 확인한다.
- 예상 교통량, 기준값, 고교통량 위험과 위험 비율이 같은 API 응답을 사용하는지 확인한다.

시험 성능을 보고 모델을 다시 튜닝하지 마라. 팀원 기여 내역은 실제 커밋을 기준으로만 README 또는 역할 문서에 기록하라. 검증이 끝난 경우에만 main을 push하라.

push 후 원격 main의 커밋 해시가 로컬 HEAD와 같은지 확인하라. 마지막 보고에는 반영한 팀원별 커밋, 전체 테스트 결과, 실제 연동 결과, 최종 main 커밋과 남은 문제를 적어라.
```
