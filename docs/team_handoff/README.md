# 팀 작업 인계

## 작업 순서

백엔드와 프론트엔드가 같은 API 계약을 사용해야 하므로 다음 순서로 진행한다.

- 이나율: `feat/backend-locations` 브랜치에서 교차로·접근로 목록 API 완성
- 김성현: 백엔드 브랜치 검토와 테스트 후 `main` 반영
- 김문일: 최신 `main`에서 `feat/streamlit-ui` 브랜치를 만들어 Streamlit 구현
- 김성현: 프론트엔드 브랜치 검토, 전체 연동 확인과 최종 통합

실제로 작성한 코드와 테스트가 각자의 브랜치와 커밋에 남아야 한다. 역할표만 작성하고 다른 사람이 만든 코드를 본인 기여로 적지 않는다.

## 전달할 자료

- GitHub: `https://github.com/haapppy23/cheonan_car_traffic_prediction_and_warning_project`
- 실행파일: `천안교통_실행파일.zip`
- 공통 설치법: `공통_시작_가이드.md`
- 이나율용: `이나율_프롬프트.md`
- 김문일용: `김문일_프롬프트.md`
- 카카오톡 전달문: `팀원에게_보낼_카톡.txt`

`천안교통_실행파일.zip`에는 Git에 올리지 않는 최종 모델, 실제 교통량 이력과 고교통량 기준이 들어 있다. 저장소를 복제한 뒤 프로젝트 최상위 폴더에 압축을 풀면 원래 경로에 배치된다.

## 완료 기준

- 이나율의 `/locations`가 교차로와 접근로 목록을 반환한다.
- 기존 `/health`와 `/predict`가 그대로 동작한다.
- 김문일의 Streamlit에서 교차로·접근로를 선택하고 예측할 수 있다.
- 예상 교통량, 고교통량 기준, 위험 여부와 위험 비율이 표시된다.
- API 연결 실패와 입력 오류가 사용자에게 읽을 수 있는 문장으로 표시된다.
- 전체 자동 테스트가 통과하고 실제 서버 연동을 한 번 확인한다.

## 이번 인계에서 하지 않는 것

- 모델 재선정이나 시험 구간 재튜닝
- 로그인, 회원 관리와 데이터베이스
- 클라우드 배포와 도메인 연결
- 지도, 실시간 센서 수집과 과도한 화면 장식
