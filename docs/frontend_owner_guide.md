# 김문일 Streamlit 프론트엔드 담당 설명서

## 이 문서의 목적

이 문서는 프론트엔드 구현 순서를 이해하고 발표와 질의응답을 준비하기 위한 개인 학습 노트이다. 현재 구현된 기능과 확인하지 않은 부분을 구분하며, 확인하지 않은 연동을 완료했다고 표현하지 않는다.

## 현재 완료된 범위

- `frontend/app.py`: 단일 Streamlit 화면
- `frontend/api_client.py`: `/health`, `/locations`, `/predict` 호출과 오류 문장 처리
- 교차로 선택에 따라 접근로 목록이 바뀌는 선택 항목
- 접근로명 `불당4_남`을 `남쪽에서 진입 (불당4_남)`으로 표시
- 기준 시각 선택: 기본은 서버의 최신 자료 시각, 필요하면 달력과 시각 목록으로 선택
- 예상 교통량, 고교통량 기준, 위험 여부, 위험 비율 표시
- 연결 실패, 404, 422, 500, 데이터 부족 응답을 사용자 문장으로 표시
- `tests/test_frontend_api_client.py`: API 호출 함수의 정상·오류 응답 자동 테스트
- `frontend/README.md`: 백엔드와 프론트엔드 실행 순서

## 확인이 필요한 범위

- 실행파일을 사용한 FastAPI와 Streamlit 실제 연동 확인
- `/locations` 응답 형식 (이나율 백엔드 작업이 `main`에 반영된 뒤 확인)

## 내가 담당하는 범위

김문일의 주 담당은 사용자 화면이다.

```
FastAPI 응답 확인
→ API 호출 함수 작성
→ 교차로·접근로·기준 시각 선택 화면
→ 예측 결과 표시
→ 오류 문장 처리
→ 자동 테스트와 실제 연동 확인
```

화면은 모델 파일을 직접 불러오거나 lag·이동 평균·경보 기준을 계산하지 않는다. 모든 값은 FastAPI에서 받는다.

## 전체 프로젝트에서 프론트엔드의 위치

```
천안시 원본 데이터
→ 데이터·ML 담당: 정제와 학습, 최종 모델과 입출력 규격
→ 백엔드 담당: FastAPI로 모델 호출
→ 프론트엔드 담당: Streamlit에서 사용자에게 결과 표시
```

## 화면 흐름

1. 화면이 열리면 `GET /health`로 서버 연결을 확인한다. 실패하면 안내 문장을 보여주고 멈춘다.
2. `GET /locations`로 교차로 12개와 접근로 44개 목록을 받아 선택 항목을 만든다.
3. 사용자가 교차로, 접근로, 기준 시각을 고른다. 백엔드는 예측할 시각(`target_timestamp`)을 받으므로 화면은 기준 시각 + 1시간을 보낸다. 최신 자료 기준이면 시각을 보내지 않고, 서버가 마지막 관측의 1시간 후를 예측한다.
4. **예측하기**를 누르면 `POST /predict`를 호출한다.
5. 응답의 네 값을 표시한다.

| 응답 필드 | 화면 표시 | 의미 |
|---|---|---|
| `predicted_volume` | 1시간 후 예상 교통량 | 0 이상의 예측 차량 수 |
| `high_traffic_threshold` | 고교통량 기준 | 접근로별 학습 기간 90백분위수 |
| `high_traffic_alert` | 고교통량 위험 / 보통 | 예상 교통량 > 기준 |
| `risk_score` | 위험 비율 (기준 대비 %) | 예상 교통량 ÷ 기준. 확률이 아니다 |

응답 규격은 `docs/model_handoff.md`를 따른다.

## 표시 원칙

- 위험일 때 "고교통량 위험"으로 쓰고 "정체"라고 쓰지 않는다. 속도·통행시간 자료가 없기 때문이다.
- 시험 구간 성능을 화면에 실시간 정확도처럼 표시하지 않는다.
- 접근로 방향은 원본 접근로명에 들어 있는 진입 방향을 그대로 쓴다. 화면에서 새로 추정하지 않는다.
- 지도, 로그인, 데이터베이스, 애니메이션과 과도한 CSS는 넣지 않는다.

## 오류 처리

| 상황 | 화면 문장 |
|---|---|
| 서버가 꺼짐 | 예측 서버에 연결할 수 없습니다. FastAPI 서버가 실행 중인지 확인해 주세요. |
| 응답 지연 | 예측 서버의 응답이 늦습니다. 잠시 후 다시 시도해 주세요. |
| 404 | 선택한 교차로·접근로 또는 시각의 자료가 없어 예측할 수 없습니다. |
| 422 (168시간 이력 부족 포함) | 이 시각은 예측할 수 없습니다. 예측 직전 1주(168시간) 교통량 이력이 부족하거나 입력값이 올바르지 않습니다. |
| 168시간 이력 부족 | 예측에 필요한 과거 교통량 자료가 부족해 예측할 수 없습니다. |
| 그 밖의 오류 | 예측 서버에서 오류가 발생했습니다. (HTTP 코드) |

## API 호출 코드를 화면과 분리한 이유

Streamlit 화면은 자동 테스트가 어렵다. 호출과 오류 처리를 `api_client.py`에 모으면 Streamlit 없이 정상 응답과 오류 응답을 테스트할 수 있다. 테스트는 로컬에 임시 HTTP 서버를 띄워 실제 요청을 보내는 방식이다.

## 실행 순서

```bash
python -m pip install -r requirements.txt
python -m uvicorn backend.app:app --reload     # 터미널 1
streamlit run frontend/app.py                  # 터미널 2
python -m pytest -q                            # 테스트
```

API 주소는 환경변수 `TRAFFIC_API_URL`로 바꾼다. 기본값은 `http://127.0.0.1:8000`이다.

## 문제 발생 시 확인 항목

- **연결할 수 없다는 문장**: FastAPI 터미널이 켜져 있는지, 주소가 `TRAFFIC_API_URL`과 같은지 확인한다.
- **교차로 목록이 비어 있음**: 브라우저에서 `http://127.0.0.1:8000/locations`를 열어 응답을 확인한다.
- **직접 고른 시각이 반영되지 않음**: `http://127.0.0.1:8000/docs`에서 `/predict`의 시각 필드 이름을 확인한다.
- **`streamlit` 명령을 찾을 수 없음**: `python -m streamlit run frontend/app.py`로 실행한다.

## 예상 질문과 짧은 답변

### 화면에서 모델을 직접 돌립니까?

아닙니다. 화면은 FastAPI만 호출합니다. 모델과 고교통량 기준은 서버가 시작할 때 한 번 불러옵니다.

### 사용자가 과거 교통량을 입력합니까?

아닙니다. 사용자는 교차로, 접근로, 기준 시각만 고릅니다. 과거 교통량과 시간 특성은 서버가 저장된 자료에서 만듭니다.

### 동쪽, 남쪽은 무엇을 기준으로 한 방향입니까?

원본 데이터의 접근로명이 진입 방향을 포함합니다. `불당4_남`은 불당4 교차로의 남쪽 접근로로 들어오는 차량입니다. 화면은 이 이름을 읽기 쉽게 바꿔 보여줄 뿐 방향을 새로 정하지 않습니다.

### 위험 비율 112%는 112% 확률로 막힌다는 뜻입니까?

아닙니다. 예상 교통량이 그 접근로의 평소 상위 10% 기준보다 12% 많다는 뜻입니다. 접근로마다 기준이 143대에서 2,672대까지 달라서 기준 대비 비율로 보여줍니다.

### 왜 "정체"라고 하지 않습니까?

통행량 자료만 있고 속도나 통행시간 자료가 없어서 실제 정체를 확인할 수 없기 때문입니다.

### 위험이 아니라고 나오면 안 막힙니까?

보장하지 않습니다. 최종 모델은 시험 구간 실제 고교통량 7,073건 중 1,928건을 놓쳤습니다(Recall 0.727). 그래서 화면에 참고용 위험 신호라고 안내합니다.

### 서버가 꺼지면 어떻게 됩니까?

화면이 멈추지 않고 "예측 서버에 연결할 수 없습니다"라는 문장을 보여줍니다. 자동 테스트로도 확인합니다.

## 발표용 전체 요약

> 프론트엔드 담당은 Streamlit으로 사용자 화면을 만들었습니다. 사용자는 교차로, 접근로, 기준 시각만 고르고, 화면은 FastAPI의 `/locations`와 `/predict`를 호출해 1시간 후 예상 교통량, 접근로별 고교통량 기준, 위험 여부와 기준 대비 위험 비율을 보여줍니다. 화면은 모델을 직접 계산하지 않으며, 서버 연결 실패나 자료 부족도 사용자가 이해할 수 있는 문장으로 안내합니다. 속도 자료가 없으므로 결과는 정체가 아니라 고교통량 위험으로 표현합니다.
